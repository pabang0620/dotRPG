# dotRPG 에이전트 공통 규칙

레포 루트: `/mnt/c/Users/admin/Desktop/games/dotRPG`. 서버 `server/`(Node.js/TypeScript/Express/PostgreSQL), 클라이언트 `Assets/Scripts/Runtime/`(C#, Unity 6000.5.9f1). 다른 작업자(jaein)와 공유하는 레포다.

## 브랜치·git
- 브랜치는 `wonho`다. 확인만 하고 checkout·브랜치 생성은 하지 않는다. `jaein`·`main`은 건드리지 않는다.
- git 쓰기 명령(add, commit, checkout, reset, stash, restore, rm) 금지. 커밋·푸시는 메인이 한다. `git status`, `git diff`, `git show HEAD:<경로>` 같은 읽기는 된다.

## 동시 작업
- 다른 에이전트가 같은 브랜치에서 동시에 일한다. 스폰 프롬프트가 지정한 파일·폴더만 수정하고 그 밖은 읽기만 한다. 소유 밖 파일을 고쳐야 하면 멈추고 보고한다.
- Bash가 있는 에이전트는 시작할 때 `git status --short`로 이미 바뀐 파일을 적어 두고 그 파일은 손대지 않는다(사용자·다른 세션 작업물).
- 분담·충돌 우려는 묻지 않고 스스로 판단해 진행하고, 보고에 한 줄로만 적는다.

## 하지 않는 것
- Unity 컴파일·빌드·게임 실행. 서버 전체 테스트 실행. 모두 메인이 묶음 끝에 1회 한다.
- 일정·기간 견적. 스폰 프롬프트가 "확정"이라고 적은 사용자 요구를 바꾸는 것.
- 설계 문서에 없는 테이블·API 추가(멈추고 보고). 단, 스폰 프롬프트가 "이 프롬프트가 설계를 대신한다"고 밝히면 새 테이블·API가 없는 범위에서 그 지시대로 진행한다.

## 서버 검증 (서버 에이전트)
- `cd server && npx tsc --noEmit`. 다른 에이전트가 동시에 고치는 파일의 오류는 무시하고 자기 파일 오류만 0으로 만든다.
- 자기 테스트 파일만 `npm test -- <이름> [<이름> ...]`로 한 번에 묶어 돌린다(실행마다 embedded-postgres를 새로 띄우므로 나눠 돌리지 않는다). 테스트 파일은 `server/test/<이름>.test.ts`, 도우미는 `test/helpers.ts`·`test/*Helpers.ts`.
- 테스트만 쓰는 작업에서 버그를 찾으면 고치지 말고 그 케이스를 `it.todo`(주석에 "버그: ...")로 남기고 보고한다.
