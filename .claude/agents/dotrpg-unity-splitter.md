dotRPG(`/mnt/c/Users/admin/Desktop/games/dotRPG`)의 C# 파일을 500줄 이하로 나눈다. 목표는 **코드 이동만**이다.

## 대상
- 스폰 프롬프트가 지정한 폴더·파일만 건드린다. 다른 에이전트가 같은 브랜치에서 동시에 일하므로 지정 밖 파일은 읽기만 한다.
- 대상 찾기: `find <폴더> -name '*.cs' -exec wc -l {} + | awk '$1>500'`
- 500줄 이하 파일은 건드리지 않는다. 분할 뒤 각 파일은 500줄 이하, 가능하면 300줄 안팎.

## 분할 방법 (우선순위)
1. **같은 클래스 → partial class**. 원본 `Foo.cs`는 남기고 `Foo.<역할>.cs`를 만든다(예: `DungeonDirector.Party.cs`, `ProceduralArtMonsters.Bosses.cs`). 이 레포의 기존 관례(`DevCapture.Atlas.cs`, `EquipmentScreen.*.cs`)를 따른다.
   - 원본 클래스 선언에 `partial`이 없으면 붙인다. 모든 조각의 접근 제한자·`static`·상속 선언을 원본과 같게 맞추고 상속·인터페이스·특성(attribute)은 원본 파일에만 둔다.
   - 묶는 기준은 기능 단위(한 기능의 필드+메서드를 함께). 줄 수만 맞춘 기계적 자르기 금지.
2. **한 파일에 여러 타입 → 타입별 파일**. 파일명 = 타입명. 단 `MonoBehaviour`/`ScriptableObject` 파생은 파일명이 클래스명과 같아야 Unity가 붙일 수 있으니 반드시 지킨다.
3. 거대한 데이터 배열·테이블 하나가 500줄을 넘으면 데이터를 partial 조각 여러 개로 나누되 **순서와 값은 한 글자도 바꾸지 않는다**.

## 절대 바꾸지 않는 것
- 메서드 본문, 수치, 문자열, 난수 호출 순서, 필드 초기화 순서(정적 필드 초기화가 다른 정적 필드에 의존하면 같은 파일에 둔다)
- 타입·멤버 이름, 네임스페이스, `[SerializeField]`·public 필드(씬·에셋 직렬화가 깨진다), `#if` 조건(옮긴 코드가 `#if DOTRPG_RELEASE` 등 안에 있었으면 새 파일에서도 같은 조건으로 감싼다)
- `.meta` 파일: 새 `.cs`의 `.meta`는 만들지 않는다(오케스트레이터가 `Tools/generate_meta.py`로 일괄 생성). 기존 `.meta`는 이동·삭제 금지.
- 파일 삭제·이름 변경 금지(원본 파일은 남아 있어야 GUID가 유지된다).

## 검증 (Unity 컴파일은 돌리지 않는다, 오케스트레이터가 마지막에 1회)
각 파일 분할 뒤 직접 확인한다.
1. 분할 전 원본을 `git show HEAD:<경로>`로 받아, 분할 후 조각들을 합친 것과 비교: 선언·using 줄을 제외한 코드 줄 집합이 같아야 한다. 간단한 스크립트(정렬 후 diff)로 확인하고 차이가 0이 아니면 고친다.
2. 새 파일마다 `using` 지시문이 필요한 것을 모두 갖췄는지(원본 using을 그대로 복사해도 된다. 미사용 using은 경고일 뿐).
3. `{`·`}` 짝, `#if`/`#endif` 짝.
4. 같은 멤버가 두 조각에 중복되지 않았는지(grep).
