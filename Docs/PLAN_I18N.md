# 다국어 지원 계획 (한국어 원문 + 11개 언어)

## 1. 작업 시작 때 규모 (2026-10-13 실측)
| 위치 | 양 | 비고 |
|---|---|---|
| 클라이언트 C# 문자열 | 287개 파일, 3,471곳 (서로 다른 문장 2,889개) | 그중 `$"..."` 보간 639곳. 상위: GearCatalog 324, CareerData 102, DungeonDatabase 77, MenuScreens 75 |
| 대사·퀘스트 데이터 | StoryDialogues 825, Quests 419, Cutscenes 193, Dialogues 66, StoryWorld 7 | `Assets/Resources/Data/*.json`, 약 3.6만 자 |
| 서버 사용자 노출 메시지 | `new AppError(...)` 576곳 | 모두 오류 코드(`code`)가 같이 있다 |
| 서버 데이터 | items, monsters, careers, dungeons, daily_quests, star_products, chat, reserved_names, banned_words | 이름이 응답에 실려 클라이언트 화면에 나온다 |
| 기존 장치 | `SettingsData.language = "ko"` 필드만 있고 쓰는 곳 없음. 글꼴 Galmuri는 영문 포함. TextMeshPro 미사용(uGUI Text, 생성 지점은 `UIFactory.Text` 하나) | |

맵 txt의 한국어는 주석이라 대상이 아니다. `DevCapture*`(촬영·측정 도구)는 대상에서 뺀다.

## 2. 방식 결정
**한국어 원문을 키로 쓰는 번역표**(gettext 방식)로 간다.
- 코드: `L.T("한국어 원문")`, 보간은 `L.F("{0}을(를) 샀습니다.", name)`. 영어 모드에서 표에 없으면 한국어를 그대로 보여 준다(깨지지 않음).
- 이유: 2,889개 문장마다 ID를 새로 짓는 방식은 코드가 읽기 어려워지고 작업량이 두 배다. 원문 키 방식은 서버나 데이터에서 온 한국어 이름(경매 물품명, 우편 제목 등)도 화면에 띄우는 자리에서 같은 표로 바꿀 수 있다.
- 같은 한국어가 뜻이 다를 때만 문맥 키 `L.T("열기", "door")`를 쓴다.
- 조사: `을(를)`, `Josa(...)`는 영어 모드에서 빈 문자열로 처리한다. 영어 문장은 번역표 쪽에서 자연스럽게 다시 쓴다.
- 이름(아이템·몬스터·스킬·직업·지역): 비교·저장·서버 전송에 쓰이지 않는 클라이언트 카탈로그는 **만드는 지점 한 곳에서** `name = L.T(name)`으로 바꾼다(GearCatalog라면 251행 한 줄). `diff.name == DungeonDatabase.RaidHeroicName`처럼 이름을 비교하거나 저장하는 것은 정의를 그대로 두고 **화면에 띄울 때** `L.T(x.name)`. 서버에서 받은 한국어 이름(경매 물품, 우편)도 표시 지점에서 `L.T`. `L.T`는 이미 영어인 문장을 그대로 돌려주므로 두 번 거쳐도 안전하다.
- 카탈로그 배열처럼 이름만 늘어선 구간은 `// i18n-names-begin` / `// i18n-names-end`로 감싸 검사 도구가 "감싸지 않은 문장"으로 세지 않게 한다. 로그(`Debug.Log*`), `[Tooltip]`, 줄 끝 `// i18n-ignore`도 제외.
- 언어 변경은 **다시 시작하면 적용**한다. 열린 화면 전부를 즉시 다시 그리는 장치는 만들지 않는다.
- 첫 실행 기본값: 새로 설치한 기기는 기기 언어가 목록에 있으면 그 언어, 없으면 `en`(`L.DeviceDefault`). 언어 항목이 없던 시절의 기존 설정 파일은 `ko`로 둔다(`SettingsManager`). 설정 화면에서 바꾼다.

## 3. 번역표 파일
- `Assets/Resources/Data/Lang/<코드>/*.json` (분야별, 영어 기준 `ui1.json`, `ui2.json`, `names.json`, `story.json`, `quests.json`, `context.json`, `system.json`, `policy.json`, `rename.json`). 실행 중에는 하나로 합친다.
- 형식: `{ "한국어 원문": "English" }`. 서버가 쓰는 표 `server/data/lang.<코드>.json`은 `python3 Tools/i18n/i18n.py sync-server`로만 만든다(직접 고치지 않는다).
- 용어집 `Docs/I18N_GLOSSARY.md`를 먼저 확정한다(직업, 전직, 각성기, 재화, 등급, 지역, 보스, 시스템 이름). 번역은 모두 이 용어집을 따른다.

## 4. 도구 (`Tools/i18n/`)
- `i18n.py extract <언어>`: C#의 `L.T`/`L.F` 인자와 데이터 JSON의 표시 필드를 모아, 번역표에 없는 항목을 `Temp/i18n/missing_<언어>.json`으로 뽑는다. `i18n.py sync-server`는 서버 표를 만들고, `i18n.py unwrapped [폴더]`는 감싸지 않은 한국어 문장을 보인다.
- `i18n.py check`: (1) 아직 `L.T`로 감싸지 않은 한국어 리터럴 개수(DevCapture 제외), (2) 영어 빈칸 개수, (3) `{0}` 자리표시자·`<color>` 태그 개수가 원문과 다른 항목, (4) 용어집과 다른 번역을 보고한다. 목표는 모두 0.

## 5. 단계
| 단계 | 내용 | 담당 |
|---|---|---|
| P0 기반 | `L` 클래스(표 로드, T/F, 조사 처리), 언어 설정·첫 실행 기본값·설정 화면 항목, `ApiClient`가 `X-Lang` 헤더 전송, 도구 2종, 용어집 초안 | 메인 |
| P1 코드 감싸기 | 287개 파일의 한국어 리터럴을 `L.T`/`L.F`로 바꾼다(문장 변경 없음, 동작 동일). 이름은 표시 지점에서 `L.T(item.name)` | fork 4~5개, 폴더별 소유 분할 |
| P2 번역 | `i18n.py extract`로 뽑은 목록을 분야별로 나눠 번역. 용어집 준수, UI 문구는 짧게 | fork 분야별 병렬 |
| P3 데이터·서버 | 대사·퀘스트·컷신 JSON 표시 필드를 로더에서 `L.T` 통과. 서버 `errorHandler`가 `X-Lang: en`이면 `server.json`으로 메시지 교체(호출부 576곳은 그대로). 서버 데이터 이름은 클라이언트 표시 지점에서 변환. 영어 금칙어·예약 이름 추가 | 메인 + dotrpg-backend-coder |
| P4 화면 맞춤 | 영어가 길어서 넘치는 곳: 버튼은 이미 `FitInFrame`으로 줄어든다. 그 밖의 고정 칸은 영어 모드에서 `resizeTextForBestFit` 최소 크기 적용. 한국어가 박힌 그림(로고, 컷인 글자) 확인 | 메인 |
| P5 마무리 | `i18n.py check` 전부 0, 컴파일, 서버 테스트, 문서 갱신. 화면 확인은 사용자 | 메인 |

## 6. 위험과 대응
- **보간 문장 순서**: 영어는 어순이 달라 `{0}` 위치가 바뀐다. 보간은 전부 `L.F` 자리표시자로 바꿔서 번역표가 순서를 정하게 한다.
- **잘게 이어 붙인 문장**: `"레벨 " + lv + " 필요"` 같은 조립은 P1에서 한 문장 `L.F("레벨 {0} 필요", lv)`로 합친다.
- **이름 비교 코드**: 정의 시점 번역 금지(2절)로 막는다. P1 fork에 "이름 상수·비교 대상은 감싸지 않는다"를 규칙으로 준다.
- **서버 메시지**: 코드 기반 클라이언트 문구가 이미 있는 곳은 클라이언트 쪽이 우선이다. 서버 번역은 나머지 안전망.
- **채팅·캐릭터 이름**: 사용자가 쓴 글은 번역하지 않는다.
- **번역 누락**: 한국어로 보일 뿐 깨지지 않는다. `i18n.py check`로 0까지 줄인다.

## 7. 다국어 확장 (2026-10-13 사용자 지시 "일본어나 타언어 아무튼 다국어 다 넣어줘")
- 언어(코드): 한국어 ko, 영어 en, 일본어 ja, 간체 중국어 zh-Hans, 번체 중국어 zh-Hant, 스페인어 es, 브라질 포르투갈어 pt-BR, 독일어 de, 프랑스어 fr, 러시아어 ru, 베트남어 vi, 인도네시아어 id. 목록은 `L.Languages` 한 곳.
- 표: `Resources/Data/Lang/<코드>/*.json`, 서버는 `server/data/lang.<코드>.json`(`i18n.py sync-server`가 만든다. 폴더로 두면 데이터 폴더를 복사하는 서버 테스트가 깨진다).
- 서버는 X-Lang 값이 목록에 있을 때만 그 파일을 읽는다(헤더가 파일 이름이 되므로).
- 글꼴: Galmuri가 일본어·키릴·라틴 확장·베트남어를 모두 갖고 있다. 중국어(간체는 절반만 있음)는 기기 CJK 글꼴(`UIFont.Get`)로 바꾼다.
- 태국어·아랍어는 뺐다. uGUI 기본 Text가 결합 부호 배치와 오른쪽에서 왼쪽 쓰기를 못 한다.
- 언어마다 다른 처리:
  - 요일 약자는 문맥 키 `day|월`로 둔다.
  - 큰 숫자: 한국어·일본어·중국어는 만/억 단위(`unit|만`), 그 밖의 언어는 M/B.
  - 조사(`L.Josa`)는 한국어만 붙인다.
- 번역 방식: 한국어 원문과 영어 번역을 함께 주고, 언어마다 3묶음으로 나눠 번역한다. A는 고유명사·퀘스트, B는 UI, C는 대사·시스템이다. A를 먼저 끝내고, B와 C는 그 언어의 A 결과에서 이름을 가져다 쓴다.

## 8. 범위 밖
스토어 페이지(Steam·Play) 영어 설명, 광고 영상 영어판, 관리자 화면. 필요하면 따로 진행한다.

## 9. 진행 상황 (2026-10-13)
- 끝난 단계
  - P0 기반: `L` 클래스, 설정의 언어 항목, 서버 X-Lang 처리.
  - P1 감싸기: 문장 약 3,200곳.
  - P2 번역: 11개 언어 x 4,456키. 영어는 Opus, 나머지 10개 언어는 영어를 중간 기준으로 Sonnet이 번역.
  - P3 데이터·서버: 대사·퀘스트·컷신, 서버 메시지 1,265개, 탈퇴 확인 문구를 언어별로 받음, 영어 금칙어.
- 검사 결과: `i18n.py check` 기준으로 모든 언어가 미번역 0, 자리표시자·태그 불일치 0.
- 남은 일
  - P4 화면 맞춤: 긴 언어(독일어·러시아어 등)에서 칸을 넘치는 곳은 화면을 보고 고친다. 버튼은 `FitInFrame`이 줄여 준다.
  - 정책 문서는 서버 `server/policies/{ko,en}/`에 한국어와 영어만 있다. 약관 동의 화면과 약관 및 정책 메뉴의 클라이언트 문구는 11개 언어 번역표(`policy.json`)를 쓴다. 법률 검토는 따로 필요하다.
  - 원어민 감수: 번역은 기계 번역 수준이므로 출시 전에 언어별 감수가 필요하다. 특히 러시아어는 주인공 과거형을 남성형으로 통일했다.
- 문장을 고치거나 새로 넣을 때 순서
  1. 코드에 `L.T`/`L.F`를 쓴다.
  2. `i18n.py extract <언어코드>`로 빠진 키를 뽑아 번역한다.
  3. `i18n.py check`를 돌린다.
  4. `i18n.py sync-server`로 서버 표를 만든다.
