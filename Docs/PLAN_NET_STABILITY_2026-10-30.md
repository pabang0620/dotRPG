## 3. 고친 것

서버(옛 클라이언트와 새 클라이언트 둘 다 그대로 동작):

1. 종료 절차 6단계에 단계별 상한(HTTP 3초, 관리 서버 1초, DB 풀 3초). 배포 때 끊긴 시간이 30초에서 몇 초로 준다. timing 에 `http_ms`, `*_capped` 가 남아 어디서 막혔는지 보인다 (`server/src/server.ts`)
2. 채팅 프레임 스키마를 `z.object`로(모르는 필드는 지우고 받음). 모르는 프레임 종류는 `UNKNOWN_FRAME` 오류만 보내고 위반으로 세지 않음. 형식이 틀린 town.pos 는 그 프레임만 버림. 아는 프레임의 형식 오류는 전처럼 위반 (`wsProtocol.ts`, `wsServer.ts`)
3. FLOOD 를 3초 창으로 셈(초당 10 x 3초 = 30). 평균 한도는 같고 짧은 몰림만 허용 (`wsServer.ts`)
4. 채팅 연결 종료를 `ws.closed` 로그로 남김(정상 1000·1001은 debug). 다음 조사 때 근거가 된다 (`wsServer.ts`)
5. 중계 hello·leave 도 모르는 필드를 지우고 받음, 인증된 연결의 모르는 제어 프레임은 오류만 (`relayServer.ts`)
6. 교착(40P01)·직렬화 실패(40001) 때 요청 전체를 최대 3번 다시 실행하는 `retryOnDeadlock`. GET /party, 파티 런 하트비트, 처치 보고(request_id 멱등)에만 씀 (`db/pool.ts`, 각 컨트롤러)

클라이언트:

1. GET 은 429·503·응답 유실 때 Retry-After(최대 5초) 또는 1초·2초 뒤 두 번까지 다시 읽는다 (`ApiClient.cs`)
2. 토큰 갱신을 기다린 호출도 실제 갱신 결과를 받는다 (`ApiClient.cs`)
3. 채팅 연결: 4005는 영구 정지 대신 백오프 재접속(4초부터), 4004·4002는 토큰을 갱신하고 다시 접속. 갱신 토큰이 거절돼 지워졌을 때만 "다시 로그인해 주세요". 계정 자체의 종료(4001 다른 곳 접속, 4003 정지, 4426 업데이트, 4012 탈퇴)는 그대로 멈춘다 (`ChatSocket.cs`)
4. 중계 연결이 다시 ready 되면 `Failed` 를 끈다 (`RelayTransport.cs`)
5. 필드 입장·나가기는 같은 request_id 로 다시 보낸다(`PostIdempotent`, 429 Retry-After·응답 유실) (`FieldSession.cs`)
6. 판 정보 읽기는 한 번에 하나만 (`PartyRunSession.cs`)

### 자동 (조용히, 백오프)

| 상황 | 감지 | 동작 | 위치 |
|---|---|---|---|
| 채팅·마을 연결 끊김 | 소켓 종료, 40초 무응답 | 1~30초 백오프 재접속(원래 있음) + 위 3번으로 영구 정지 경로 제거 | `ChatSocket` |

### 수동: 일시정지 메뉴 "연결 다시 맞추기"

온라인 캐릭터로 플레이할 때만 메뉴에 나온다. 누르면 메뉴가 닫히고 "연결을 다시 맞추는 중입니다." 안내가 뜬다. 5초 안에 다시 누르면 "잠시 후 다시 눌러 주세요."

① 채팅·마을 연결을 닫고 바로 새로 연결(계정 종료 상태면 그대로) ② 파티 던전 판이 있으면 판 정보를 다시 읽고 중계 연결을 새로 붙임(좌석은 유지, 서버가 옛 연결을 새 연결로 바꿈). 판 세션이 없는데 아직 던전 안이면 다음 파티 조회에서 서버에 남은 판에 다시 붙을 수 있게 함(방장은 던전을 다시 시작하지 않음) ③ 필드 세션을 나갔다 다시 들어감 ④ 파티 정보를 바로 다시 읽음.
로그아웃하지 않고 파티도 나가지 않는다.

### 상태 표시

화면 위쪽(매칭 대기 막대 아래)에 "서버에 다시 연결하는 중..." 한 줄. 채팅·마을 연결이 재접속 중이거나, 전투 연결에서 방장이 안 보일 때 2초 넘게 이어지면 보인다. 판이 끝난 뒤와 방이 영구로 닫힌 경우는 표시하지 않는다 (`NetRecovery.Reconnecting`, `UI/NetStatusIndicator.cs`).
