# UI 감사 (E1)

## 2026-10-30 가독성 정리 + 봉화 UI 원칙 적용

사용자 요청: "UI가 겹치거나 깨지는 게 너무 많아서 가독성 좀 챙겨 줘", 그리고 봉화(냥이 성문 수비대)에 반영한 UI 전문가 피드백 원칙을 dotRPG 전체 창에 적용.

### 방법

- 기존 자동 검수(`DevCapture.UiAudit*.cs`, `server/scripts/ui-audit-*.mjs/ts`)는 빌드한 플레이어나 에디터 플레이 모드에서 `-uiAudit 1`로 실제 창을 열고, 글자마다 `preferredWidth/Height`와 상자 크기를 비교해 `height-clipping`, `width-overflow`, `outside-screen`, `single-hangul-line` 후보를 JSON에 적고 `PresentationShot`으로 캡처한다. 화면 캡처와 게임 실행이 필요해서 이번에는 쓰지 않았다(사용자가 플레이 중, 빌드 금지).
- 대신 정적 검사 `Tools/ui_static_audit.py`를 새로 만들었다. `Button / Label / Cell / UIFactory.Text+Place` 호출에서 상자 크기와 글자 크기를 읽고, 11개 언어 표(`Assets/Resources/Data/Lang`) 중 가장 긴 번역의 폭을 어림한다(한글·한자·가나 1.0 x 크기, 나머지 0.55 x, 공백 0.3 x, `{n}`은 숫자 4개). 찾는 것: 버튼 글자가 14 px 아래로 줄어야 들어감(`btn-shrink`), 한 줄 상자 넘침(`oneline-over`, `cell-over`), 줄 수 넘침(`label-over`), 자동 축소 하한이 14 px 미만(`min-font`), 같은 부모·같은 기준점 형제 사각형 겹침(`overlap`). 동적 문구는 같은 파일의 `x.text = L.F(...)` 대입만 따라가므로 모든 경우를 잡지 못한다. 겹침 후보 중 번갈아 보이는 버튼(받기/진행 중 등)은 오류가 아니다.
- 최소 글자: `UiTheme.FontMin` 16은 배치 단위이고 `UIFactory.Text`가 `TextScale` 0.88을 곱해 실제로는 14 px로 그린다. 자동 축소(best fit) 하한도 이 14 px(`UIFactory.ReadableFloor`)로 맞춘다. 이전에는 버튼 글자(`FitInFrame`)가 11 px, 표 칸(`OneLine(shrink)`)이 11 px까지 줄어들 수 있었다.

재검수 상세:
- `final2-ko_100` 및 `final2-de_130`: 던전 배너·설명·보상 등급, 미니던전 카드, 강화·계승, 결과 실패 글자, 외형 목록, 상점 NPC 헤더의 겹침 해결을 원본 이미지로 확인했다.
- `final3-en_100` 및 `final3-de_130`: 파티 헤더가 탭과 분리됐고, 용병 설명의 스크롤바와 마지막 스킬·무기 문구까지 확인했다. 스킬/젬 소개와 목록의 하단 접근도 확인했다.
- 특화 hover를 추가로 열어 수호자의 짧은 설명이 한 줄 라벨로 취급되어 오른쪽으로 넘치는 문제를 발견했다. 제목과 본문을 명시적으로 나눠 수정했고 재촬영한다.
- 전직 카드의 보조 노드가 윗 카드 아래쪽 14px를 덮는 기존 배치도 발견했다. 전체 높이 안에서 행 간격을 조정했으며 재촬영한다.

자동 후보 중 던전 파티의 `나`, 난이도의 `왕`은 원래 한 글자인 별도 항목이므로 줄바꿈 오류로 세지 않는다. 마스크 안 스크롤 콘텐츠의 화면 밖 좌표도 오류로 단정하지 않는다. 최초 `initial-ko_100`의 검은 캡처는 ReadPixels 호출 오류로 무효다. `render1-ko_100`의 전투 `기절` 글자는 render-texture 캡처의 world/UI 정렬 차이에 의한 것으로, 실제 메뉴 결함과 구분하고 캡처 정렬을 보정했다. 최종 검수는 수정 후 화면을 기준으로 한다.

아래 E1 항목은 이전 감사 기록이다. 현재 버전의 미해결 목록으로 그대로 간주하지 않으며, 2026-10-27 실제 재검수 결과는 위 표와 캡처 기록을 기준으로 한다.

근거: 코드(Assets/Scripts/Runtime/UI/*.cs) + 기존 스크린샷(`merge/Logs/m_*`, `content/Logs/c3_*`, 1920×1080 / 1280×720).
기준 해상도: CanvasScaler 1280×720 기준. 아래 픽셀 값은 모두 720p 기준 단위.

우선순위: **P0** = 플레이 중 정보가 가려지거나 읽을 수 없음 · **P1** = 상용 품질에 못 미침(일관성·피드백) · **P2** = 다듬기.

## 5. 해상도별

- 1920×1080 / 2560×1440: 16:9라 720p와 같은 배치(1.5×, 2×). 16px 미만 글자는 1080p에서도 작다.
- 1280×720: 상태바 우측 404 ↔ 보스 바 좌측 408 - 4px 여유뿐.
- 1280×800(16:10, 스팀덱): C7 - 겹침 발생.
- 21:9: 높이 기준이 줄어 하단 바와 토스트 간격이 좁아짐.
