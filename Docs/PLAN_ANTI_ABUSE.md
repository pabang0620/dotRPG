# 부정 행위 방지 조사와 계획 (2026-10-06)

조사 범위: 서버(`server/src`), 클라이언트(`Assets/Scripts/Runtime`), 데이터(`server/data`). 읽기만 했고 아직 아무것도 바꾸지 않았다.

## 0. 요약

- 이미 단단한 것: 재화 복사·재전송(요청 id 멱등, 트랜잭션, 행 잠금), 상점 판매가, 처치 속도·공급·화력 상한, 경매 같은 계정 차단, 이상 기록(anomaly_log)과 관리자 감시 목록·제재.
- 비어 있는 것: "같은 사람"을 알아보는 장치가 전혀 없다. 계정·로그인에 기기나 IP 기록이 없고, 동시 접속 제한도 없다. 그래서 숫자가 정상인 협조형 부정(한 사람이 두 PC로 캐리, 부계정 레이드, 부계정 골드 몰아주기)은 하나도 걸리지 않는다.

### 하

- 황금 해골 타격 수를 클라이언트가 보냄(상한 40까지 항상 최대, `kills/killService.ts:116-119`).
- 강화 천장이 아이템 개체가 아니라 (캐릭터, 아이템 종류) 단위(`enhance/enhanceService.ts:54`): 싼 같은 종류로 실패를 쌓아 비싼 것에 사용.
- story_flags를 클라이언트 값 그대로 받음(`characters/stateRules.ts:134-148`).

## 2. 원칙

1. "같은 사람"을 알아본다: 기기 id + IP + Steam 계정을 로그인마다 기록한다. 이것이 모든 다계정 대책의 바탕이다.
2. 한 기기 동시 접속은 2개까지 허용, 3번째부터 거절(사용자 결정). 같은 IP는 PC방·공유기를 고려해 거절하지 않고 감시 점수로 쓴다.
3. 보상은 기여에 비례한다: 서 있기만 한 캐릭터는 보상이 없거나 크게 깎인다.
4. 레벨 차가 큰 파티는 낮은 쪽 성장을 크게 줄인다(캐리는 "도움" 수준까지만).
5. 정상 유저 불편은 최소로: 친구 2명 파티, 두 PC 플레이는 그대로 된다.

## 3. 계획

### 1단계 (먼저, 상 등급)

| 할 일 | 내용 | 해결 |
|---|---|---|
| 기기·접속 기록 | 클라이언트가 설치 id와 기기 지문 해시(SystemInfo.deviceUniqueIdentifier 해시)를 로그인 때 보냄. 서버에 login_events(계정, 캐릭터, 기기, IP, Steam id, 시각) 테이블 | A1, B7 기반 |
| 동시 접속 제한 | 같은 계정 재로그인 시 이전 세션 종료. 같은 기기에서 동시에 접속한 캐릭터 2개 초과 거절("이 PC에서는 동시에 2개까지"). 같은 IP 동시 다수는 감시 점수 | A1, B5 |
| 레이드 사람 수 | 같은 기기(또는 같은 Steam 계정)의 멤버는 사람 1명으로 센다. 최소 기여(피해 지분 5% 이상 또는 일정 타격 수) 없는 멤버는 보상 잠금(사유 "기여 부족") | A2, B3 |
| 필드 캐리 감쇠 강화 | 감쇠 하한 0.2 -> 0.02, 격차 5부터 레벨당 15%씩. 격차 15 이상은 경험치 1. 기여 인정은 "근처"가 아니라 "직접 타격"으로(호스트 판정 변경) | A3 |
| 던전 기여 판정 | 판 피해 지분 5% 미만 멤버는 클리어 보상 잠금. 권장 레벨보다 10 이상 낮은 멤버는 클리어 XP 감쇠 | A4 |
| 처치 보고 체류 검증 | 서버가 아는 "현재 맵"(필드 세션 입장, 맵 이동 저장) 기준으로 다른 맵 처치 거절. 필드 보스는 입장 후 일정 시간 체류 필요 | A5 |
| 경매 구매자 자격 | 구매자도 Lv10·계정 7일. 쌍별 한도를 양방향 합산. 상점 판매 품목은 기준가 상한을 상점가 3배로. 상한가 체결·새 계정 구매는 성공해도 기록 | A6, B7 |
| 뽑기 장비 귀속 | 별조각 뽑기 장비는 계정 귀속 | A7 |

### 2단계 (중 등급)

| 할 일 | 내용 | 해결 |
|---|---|---|
| 퀘스트 데이터·조건 | c1s_bones·w_essence에 재료 소모 넣기(데이터 버그). 검증 불가 퀘스트는 수락 후 최소 시간 + 최소 레벨(퀘스트 지역 권장 레벨 - 5) | B1 |
| 던전 결과 검증 | 모든 난이도·레이드에 최소 클리어 시간. 파티는 피격 수를 멤버 보고 중 큰 값으로, 랭크 보너스는 기여 지분 미달이면 0 | B2 |
| 캐릭터 찍어내기 | 상자 보상·퀘스트 장비 계정 귀속, 삭제 후 재생성 캐릭터는 첫날 경매 등록 불가 | B4 |
| 자동 진행 | 클라이언트가 자동 진행 상태를 서버에 알림. 자동 진행 중 30분간 사람 입력이 없으면 자동 진행 정지 + 확인 창. 같은 기기 2개 제한과 함께 동작 | B5 |
| 가입 보호 | 속도 제한을 DB에 저장(재시작해도 유지). 시험 단계 dev 가입은 초대 코드 필요 | B6 |
| 관리자 도구 | 기기·IP로 계정 묶어 보기, 성공 거래 의심 목록, 아이템·골드 회수 | B7 |

### 3단계 (하 등급)

- 황금 해골 타격 수를 처치 시간으로 상한.
- 강화 천장을 아이템 개체 단위로.
- story_flags 중 보상과 연결된 것만 서버 기준으로.

## 4. 영향과 확인 방법

- 정상 플레이 영향: 같은 PC 2개까지, 친구 파티, 비슷한 레벨끼리 사냥은 그대로. 레벨 차 큰 캐리와 무기여 탑승만 막힌다.
- 확인: 서버 시험(시험은 사용자가 요청할 때 실행)과 이론 계산(캐리 시 시간당 XP를 다시 계산해 혼자 사냥의 1.5배 이하인지).
- 서버 변경이 많아 1단계는 dotrpg-server-architect 설계 -> dotrpg-backend-coder 구현 -> dotrpg-economy-auditor 점검 순서로 진행한다.
