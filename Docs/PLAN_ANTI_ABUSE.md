# 부정 행위 방지 조사와 계획 (2026-10-06, 2판)

조사 범위: 서버(`server/src`), 클라이언트(`Assets/Scripts/Runtime`), 데이터(`server/data`). 읽기만 했고 아직 아무것도 바꾸지 않았다.

## 0. 요약

- 이미 단단한 것: 재화 복사·재전송(요청 id 멱등, 트랜잭션, 행 잠금), 상점 판매가, 처치 속도·공급·화력 상한, 경매 같은 계정 차단, 이상 기록(anomaly_log)과 관리자 감시 목록·제재.
- 비어 있는 것: "같은 사람"을 알아보는 장치가 전혀 없다. 계정·로그인에 기기나 IP 기록이 없고, 동시 접속 제한도 없다. 그래서 숫자가 정상인 협조형 부정(한 사람이 두 PC로 캐리, 부계정 레이드, 부계정 골드 몰아주기)은 하나도 걸리지 않는다.

### 하

- 황금 해골 타격 수를 클라이언트가 보냄(상한 40까지 항상 최대, `kills/killService.ts:116-119`).
- 강화 천장이 아이템 개체가 아니라 (캐릭터, 아이템 종류) 단위(`enhance/enhanceService.ts:54`): 싼 같은 종류로 실패를 쌓아 비싼 것에 사용.
- story_flags를 클라이언트 값 그대로 받음(`characters/stateRules.ts:134-148`).
- 같은 맵 안 저장 좌표는 범위만 검사(순간이동), 경매 검색 페이지 상한 없음(DB 부하), 금칙어 6단어뿐, 초대 오류 코드로 접속 여부 조회 가능.
- 이미 안전한 것(2차 조사): 서버 시계만 사용(클라 시계 조작 무효), 오프라인 세이브를 온라인으로 가져오는 길 없음, 릴레이 서명 티켓·크기·도배 제한, 강화·승급·합성 재시도 경합 없음, 관리자 TOTP·역할·IP 제한, 리프레시 토큰 재사용 감지.

## 2. 원칙

1. "같은 사람"을 알아본다: 기기 id + IP + Steam 계정을 로그인마다 기록한다. 이것이 모든 다계정 대책의 바탕이다.
2. 한 기기 동시 접속은 2개까지 허용, 3번째부터 거절(사용자 결정). 같은 IP는 PC방·공유기를 고려해 거절하지 않고 감시 점수로 쓴다.
3. 보상은 기여에 비례한다: 서 있기만 한 캐릭터는 보상이 없거나 크게 깎인다.
4. 레벨 차가 큰 파티는 낮은 쪽 성장을 크게 줄인다(캐리는 "도움" 수준까지만).
5. 정상 유저 불편은 최소로: 친구 2명 파티, 두 PC 플레이는 그대로 된다.

## 3-1. 재화 이상 자동 정지 (A10)

목표: 플레이 시간에 비해 재화가 비정상적으로 늘면 그 캐릭터(와 연결된 계정)의 경제 활동을 일단 멈추고 운영자가 확인한다.

- 플레이 시간: 클라이언트가 30초마다 생존 신호(맵, 자동 진행 여부, 최근 입력 여부)를 보낸다. 서버는 신호 간격 60초 이하인 구간만 "활동 시간"으로 누적한다(play_time 테이블, 캐릭터별 일 단위). 이 신호가 처치 보고의 현재 맵 확인(A5)과 자동 진행 방치 감지(B5)에도 쓰인다.
- 기대 수입 상한: 레벨대별로 정상 플레이가 낼 수 있는 시간당 최대치(골드, 경험치, 강화석·정수·핵, 유니크 이상 장비 수)를 데이터에서 계산해 표로 둔다(theory_progress.py 확장). 기준은 이론 최대의 3배.
- 감시 창: 1시간, 24시간, 7일. 원장(gold_ledger, item_ledger, xp_ledger) 합계 / 활동 시간을 상한과 비교한다. 경매 수입은 따로 본다(다른 계정에서 들어온 순유입이 크고 상대가 새 계정·같은 기기면 가중).
- 정지(hold): 상한을 넘으면 그 캐릭터에 경제 정지를 건다. 정지 중에는 경매 등록·구매, 상점 판매, 강화, 별조각 사용이 "검토 중" 응답으로 멈추고, 새로 얻는 골드·아이템은 보류 원장에 쌓였다가 해제 때 지급되거나 회수된다. 사냥·이동 같은 플레이는 계속된다. 같은 기기·Steam으로 묶인 계정에도 함께 건다.
- 운영: 관리자 화면에 정지 목록과 근거(창별 수입/활동 시간/상한), 해제·회수 버튼. 자동 해제는 하지 않는다. 오탐을 줄이기 위해 처음 2주는 "기록만" 모드로 돌려 상한을 조정한다.

## 3-2. 1단계 보강 (2차 조사 반영)
