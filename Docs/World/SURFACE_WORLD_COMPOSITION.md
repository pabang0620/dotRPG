# 지상 월드 풍경과 지형 합성

## 적용 범위

지상 월드의 마을 5곳(바깥쪽 마을 4곳과 중앙 뿌리샘 마을), 사냥터 16곳에 전용 배경·지면 아트를 적용한다. 실내, 인스턴스 던전과 지하 월드는 이 경로의 대상이 아니다.

| 권역 | 맵 | 재질과 거리 표현 |
| --- | --- | --- |
| 숲 | village, forest, forest_ruins, forest_depths, forest_crossing | 따뜻한 흙길과 이끼, 가까운 수목의 짙은 색, 낮은 골짜기 쪽의 차갑고 옅은 녹색 |
| 바위절벽 | canyon, canyon_pass, canyon_mine, canyon_ridge, canyon_gate | 황갈색 암반 윗면, 두꺼운 절벽 정면, 멀어질수록 대비가 낮아지는 암주 |
| 설산 | winter, winter_edge, winter_lake, winter_peak, winter_reach | 밝은 눈바닥에서 이어지는 넓은 설사면, 큰 산체의 능선, 낮은 대비의 먼 설산 |
| 고대 성소 | sunken_sanctum, sanctum_hall, sanctum_archive, sanctum_roots, sanctum_court | 닳은 석회암, 젖은 물가, 녹색 수면, 깊고 어두운 외곽 유적 |
| 중앙 마을 | undergate | 숲의 흙과 뿌리, 기존 광장과 거목을 받쳐 주는 낮은 식생 |

## 참고와 제작 원칙

[로스트아크 뷰포인트 모음](https://www.inven.co.kr/board/lostark/4821/3098)의 로그힐 폭포 다리, 거울 계곡의 절벽, 슈샤이어 얼음 폭포 장면을 살펴보았다. 참고한 요소는 가까운 보행면 → 그 바닥을 받치는 수직 면 → 멀리 내려다보이는 풍경의 연결, 같은 방향의 조명, 거리에 따른 대비 차이다. 해당 게임의 이미지 파일을 게임 리소스로 복사하지 않았다.

각 맵의 실제 바닥과 충돌 가이드를 기준으로 새로운 그림을 제작했다. 카메라 시점을 유지한 하나의 원화 안에서 지형과 풍경을 함께 맞춘 후 런타임에서 별도 레이어로 분리한다. 원경만 따로 이동시키는 시차 효과는 사용하지 않는다. 원근은 원화의 높이 면, 크기와 명암으로 표현한다.

숲은 [Secrets of Grindea의 Arcadia 제작 과정](https://www.secretsofgrindea.com/index.php/blog/7204)도 참고했다. 길·수면·배경을 연결한 다음 수목과 작은 장식을 더하는 구성, 큰 나무와 낮은 관목 사이의 빈 공간을 살펴보고 이 게임의 기존 동선에 맞게 재해석했다. 원화의 반복 잎 무늬를 다양한 수관·뿌리·관목 군집으로 다시 그렸다. 눈꽃 권역은 추가 요청에 따라 수직 절벽과 암주 대신 넓은 설산 사면을 적용한다. 작은 삼각 산봉우리를 일렬로 붙인 후보는 채택하지 않는다.

원본과 제작 프롬프트는 `SurfaceWorldSources/*.json`, 등록된 PNG의 해시와 크기는 `surface-upscale-manifest.json`에 기록한다. 모든 리소스는 실제 생성·적용된 이미지이며 임시 대체 그림은 없다. 로컬 Real-ESRGAN으로 세부 묘사를 보강한 후 정확히 월드 1칸당 48픽셀로 등록했다. 확대 렌더링은 Point이며 게임 전체 카메라와 캐릭터 크기는 변경하지 않았다.

## 코드와 리소스

- `Assets/StreamingAssets/SurfaceWorld/*.png`: 맵마다 한 개의 지형·풍경 원화, 총 21개.
- `Assets/Scripts/Runtime/Art/SurfaceWorldArt.cs`: 원화를 원경 / 받침 지형 / 보행면·물로 분리한다. 세 레이어는 동일한 좌표·배율을 사용하고 각 픽셀은 한 레이어에만 속한다. PNG가 없거나 크기·비율이 유효하지 않으면 기존 표현을 사용한다.
- `Assets/Scripts/Runtime/World/WorldBuilder.SurfaceWorld.cs`: 기존 바닥 그림만 숨기고 합성한다. 건물, 기둥, 나무, 다리, NPC, 포털, 지형 충돌은 원래 오브젝트로 남는다. 기존 전경 가림 처리도 유지한다.
- `Assets/Scripts/Runtime/World/WorldBuilder.ForestCanopy.cs`: 숲 사냥터 4곳의 장식 나무를 수관 폭에 맞춰 띄우고, 5개 수종의 군집과 앞뒤 크기·명암 차이를 만든다. 채집 나무와 기존 고체 나무의 위치·충돌은 유지한다. 비상호작용 나무 일부는 그림만 바꾸고, 새 경계 장식은 막힌 숲 영역 안에 놓는다. 재사용하는 스프라이트 뷰는 맵 전환 시 해제하며 텍스처를 복제하지 않는다.
- `Assets/Scripts/Runtime/World/WorldBuilder.SurfaceGrounding.cs`: 새 지상 원화와 독립 소품 사이에 한 장의 32PPU 접촉 그림자를 만든다. 나무·바위·건물·고정 소품의 기존 발점과 실제 월드 bounds를 사용하며, 소품 위치나 콜라이더를 수정하지 않는다. 채집 자원과 NPC는 정적 그림자 대상에서 제외한다.
- `Assets/Scripts/Runtime/World/LivingWater.cs`: 원래 물 판정 마스크를 새 원화의 해상도에 맞춰 등록해 물결 애니메이션을 연결한다.
- `Assets/Scripts/Runtime/Core/DevCapture.SurfaceWorld.cs`: 소리 0, 별도 테스트 세션에서 전체 맵·플레이 화면과 충돌/포털/이동 검증 자료를 출력한다.
- `Tools/art/upscale_surface.py`: 원본 보관, 해상도 등록, 해시 및 Unity 메타 파일 생성 도구.

그림의 분할 마스크가 일치한다고 해서 그림 속 물가가 충돌 경계와 일치한다는 뜻은 아니다. 별도로 실제 충돌 가이드와 그림을 대조해 숲 수관, 절벽, 설원 수로가 보행 영역을 덮은 부분을 수정했다.

## 실행 검증

검증은 기존 로컬 Windows 플레이어에 새 런타임 DLL과 StreamingAssets를 반영해 수행한다. Unity 에디터 라이선스를 사용할 수 없어 전체 플레이어의 새 에디터 빌드로 검증한 것은 아니다.

전체 지상 맵 검증:

```text
dotRPG.exe -batchmode -dotrpgSurface "<결과 폴더>" -surfaceBaseline "<변경 전 결과 폴더>" -logFile "<로그 파일>"
```

특정 맵만 확인하려면 `-surfaceOnly canyon_ridge`를 추가한다. `-surfaceGroundOnly`는 기존 지면을 가이드로 출력하는 개발용 옵션이다.

검증 항목은 변경 전후 레이아웃·발 충돌·포털·도착점·서비스 위치의 동일성, 실제 입력 이동, 포털 도착점까지의 경로 연결, 레이어 합성 누락과 중복, 맵 전환 후 생성 리소스 해제, 볼륨 0이다. 최종 집계와 캡처는 `SurfaceWorldPreview`에 보관한다.

2026-10-09 최종 실행 결과는 **21개 맵, 539개 통과, 실패 0개**다. 곡선 경계 원화 21개, 접촉 그림자, 숲 군집·고사목, 협곡 부유 장식 정리를 함께 넣은 Windows 플레이어에서 확인했다. 각 맵의 로딩 측정치는 약 **0.73~4.70초**였으며, 장치와 저장장치 상태에 따라 달라진다. 이는 FPS 또는 다인 파티 부하 검증 결과가 아니다. 원본·등록 PNG·플레이어에 복사한 PNG의 SHA256, 정확한 48PPU 크기, 런타임 DLL과 고사목 파일의 일치도 별도로 검사했다.

검증 캡처에서만 개발용 카메라로 전체 맵을 촬영했다. 일반 플레이 카메라 설정과 저장 데이터는 변경하지 않았다. 로컬 체험판은 기존 Windows 실행 파일의 런타임 DLL과 StreamingAssets를 갱신한 상태다.

자동 검증은 모든 길을 사람이 직접 플레이한 것과 같지 않다. 경로 연결은 발 충돌 마스크를 탐색하고, 입력 이동은 각 맵의 짧은 왕복 구간에서 실행한다. 생성 원화의 미세한 물가·수목 경계는 추가 수동 플레이에서 조정할 여지가 있다. 고해상도 원화를 분리할 때의 맵 로딩 비용과 텍스처 메모리는 증가한다. 프레임마다 이미지를 재생성하지 않으며, 소유 리소스는 맵을 떠날 때 해제한다.

## 소품과 지면 연결 보완 — 2026-10-09

### 자연스러운 지형 경계와 재질 전환

추가 요청에 따라 넓이가 일정한 도로, 직각으로 끊긴 풍경 외곽, 잔디 위에 얹힌 듯한 소품을 다시 검토했다. [CrossCode 공식 Sapphire Ridge 소개](https://radicalfishgames.itch.io/crosscode/devlog/12675/crosscode-097-the-last-area)의 다리·수면·돌길 화면을 직접 확인해 보행면과 그 아래 수직 면의 연결, 물가의 식생과 습한 재질 전환을 살폈다. [RPG Maker 공식 숲 맵 제작 글](https://rpgmakerweb.com/blog/mapping-forests)에서는 나무를 줄지어 배치하는 대신 서로 다른 크기의 군집과 빈 공간을 만드는 구성, 덜 쓰는 길에 풀이 다시 자라는 표현을 참고했다.

숲 4개 사냥터의 길은 기존 이동 공간 안에서 흙·풀·낙엽이 섞이는 가변 폭의 보행 흔적으로 다시 그렸다. 숲 유적의 중앙 경계는 정원 울타리 같은 잎 띠 대신 이끼 낀 낮은 석축으로 해석했다. 첫 마을과 중앙 마을의 획일적인 포장도 크기와 마모가 다른 돌, 흙 틈, 풀 가장자리로 교체했다. 뿌리샘의 별 모양 연못 모서리는 젖은 곡선 암반과 수중 얕은 돌층으로 완화했다. 배경 원화와 개별 나무 사이에는 아래의 별도 접촉 그림자 레이어를 사용한다.

눈 지역 5개 맵은 [CrossCode의 Bergen Trail 개발 화면](https://www.radicalfishgames.com/?p=3710), [눈 마을 제작 화면](https://www.radicalfishgames.com/?p=4274), [Sea of Stars 공식 화면](https://store.steampowered.com/app/1244090/Sea_of_Stars/)을 검토했다. 가까운 눈기슭과 먼 설산을 같은 사면으로 연결하고, 청색 그늘과 드러난 석판으로 이동 바닥을 읽히게 했다. 직각 테두리는 큰 눈더미와 완만한 곡선 사면으로, 호수 가장자리는 굽은 청빙과 어두운 젖은 접점으로 다시 그렸다. 생성 과정에서 길 위에 추가된 큰 돌과 실제 수로를 넘은 푸른 부분은 최종 등록 전에 국소 수정했다. 산을 새 통행 공간으로 만든 것은 아니며 기존 이동 판정은 유지한다.

경계의 곡선은 그림을 흐리게 만드는 필터가 아니라 암반 어깨·물속 돌·흙과 풀의 실제 윤곽을 새로 그리는 방식이다. 이동 경로와 포털의 연결 관계는 유지하며, 개별 생성 결과를 발 충돌 마스크와 대조한다. 가이드 보존 여부만으로 시각적 정합을 통과 처리하지 않는다. 리소스와 프롬프트는 `SurfaceWorldSources/natural-*.json`에 기록한다.

협곡은 직각으로 꺾이던 외곽을 둥근 사암 어깨와 아래로 이어지는 사면, 기슭의 파손 암석으로 연결했다. 원경 암주는 채도와 대비를 낮춰 가까운 보행면과 구분한다. 성소는 밝은 마른 석재 윗면 → 어두운 젖은 옆면 → 수중 잔해 → 짙은 녹색 물의 순서로 이어진다. 계단·건축물·회랑의 직선은 인공 구조의 형태이므로 유지하고, 그 바깥의 자연 지형과 파손 윤곽을 곡선으로 다듬었다.

생성 원화의 물색 검사는 실제 0.25타일 간격 지형·발 이동 마스크와 함께 사용한다. 청록색 자체를 오류로 단정하지 않고 해당 좌표를 확대해서 수면인지, 젖은 돌인지 확인한다. 기존 보행면 위에 생긴 수중 석재와 틈은 원화에서 보정하며, 통과시키기 위해 게임 충돌을 옮기지는 않는다. 이 검사는 색상 표본 검사이므로 모든 그림과 모든 발 위치의 완전한 일치를 증명하지는 않는다.

기존 실플레이 화면의 동일 수종 세로 반복과 설원 위에 떠 보이는 밑동을 확인했다. [Blizzard 환경 아트 제작 기록](https://news.blizzard.com/en-us/article/23788294/diablo-iv-quarterly-updatemarch-2022)의 자연스러운 팔레트, 플레이 공간을 위한 시각적 여백, 소품과 조명을 함께 구성하는 원칙을 참고했다. 이번 보완은 기존 도트 소품을 유지하면서 숲 군집의 틈과 접지감을 조정한다. 타 게임 이미지를 리소스로 사용하지 않는다.

코드 검토 결과:

- 숲 추가 장식은 기존 `%` 셀 내부에만 배치한다. 포털 주변 반경 약 4타일은 새 나무 후보에서 제외하고, 같은 화면 열에서 인접한 동일 나무 그림은 다른 수종으로 바꾼다. 기존 고체 나무와 자원 오브젝트의 transform·콜라이더는 그대로다.
- 숲 사냥터 4곳의 `town_dead_0/1` 그림만 `Assets/StreamingAssets/SurfaceWorld/Props/dead_oak.png`로 교체한다. 투명 알파 경계를 잘라 사용하고, 기존 스프라이트의 월드 높이와 발 피벗 비율을 유지한다. 기존 전역 아트, 마을, 다른 권역, 채집 나무는 바뀌지 않는다. PNG가 없거나 유효하지 않으면 기존 죽은 나무를 사용한다. 새 텍스처 한 장을 맵 내에서 공유하고 TreeFade 픽셀 판독을 위해 readable로 두며, 맵을 떠날 때 생성 스프라이트와 함께 해제한다.
- 접촉 그림자는 활성화된 직접 자식 소품만 대상으로 한다. `enabled=false`, `forceRenderingOff`, 알파 0, 비활성 오브젝트, 채집 자원과 NPC는 제외한다. 구조물은 기존 BoxCollider의 남쪽 기단을 기준으로 삼고, 나무는 기존 발 피벗을 사용한다.
- 물·절벽·막힌 숲에는 그림자를 그리지 않는다. 일반 맵은 해석된 지형 셀과 기존 `LivingWater.Field.Mask`의 32PPU 물 픽셀을 함께 검사한다. 성소는 기존 `SunkenSanctumShore.IsLand` 서브셀 마스크를 그대로 사용한다.
- 물가·절벽에 닿기 전 약 0.315타일에서 8방향 여유를 검사해 접촉 그림자를 8단계로 약화한다. 새 원화의 곡선 경계 위에 그림자 마스크의 직각 절단선이 다시 생기지 않도록 한 시각 처리이며, 실제 지형/발 충돌은 그대로다. 일반 지형의 기존 절벽 TilemapRenderer와 PaintedGround는 이미 합성 경로에서 숨겨져 추가로 재렌더링되지 않는다. 성소의 독립 옹벽·기둥·계단 마감은 단차를 표시하는 구조물이므로 유지한다.
- 그림자 알파는 최대 50/255, 잎이 만드는 넓은 그림자는 최대 21/255다. 그림자가 겹치면 더하지 않고 큰 값 하나를 사용해 군집 아래가 검게 뭉치지 않게 한다. Point 텍스처와 8단계 알파를 사용하며 블러와 추가 광원은 없다.
- 지상 원화 합성 성공 후에만 그림자 레이어를 만든다. 원화가 없거나 유효하지 않으면 원래 표현으로 돌아가며, 실내·인스턴스·지하 월드에는 이 경로가 적용되지 않는다.
- 협곡 4개 사냥터에서는 새 원화의 수직 절벽·심연 위에 받침 없이 떠 있던 자동 배치 `Fantasy landmark {mapId}` 장식만 숨긴다. 기존 W/% 셀에 놓인 직접 자식 SpriteRenderer이며 콜라이더·자원·NPC·서비스가 없는지 검사한다. 실제 구조물과 원화의 암반은 유지하며 지형이나 충돌은 바꾸지 않는다. 원화 합성이 실패하면 기존 장식도 그대로 표시한다. QA 메타데이터의 `hiddenUnsupportedLandmarks`로 개수를 확인할 수 있다.
- 생성 텍스처와 스프라이트는 맵 소유 컴포넌트가 해제한다. 원본 텍스처, 나무 가림, YSort, 포털·서비스·조우 데이터는 변경하지 않는다. QA는 이 추가 리소스도 맵 전환 해제 검사에 포함한다.

추가 캡처는 대표 4개 맵의 `*-vista-environment.png`다. 플레이 화면과 같은 카메라 위치에서 잠시 HUD·캐릭터·전투 이펙트만 숨긴 뒤 즉시 원상복구한다. `*-vista-gameplay.png`에는 기존 HUD와 실제 플레이 오브젝트가 남는다. 최신 코드의 Roslyn 컴파일과 최종 21맵 네이티브 검증을 완료했으며 결과는 위의 539개 집계와 `SurfaceWorldPreview/report.txt`에 포함된다. 협곡 4개 사냥터에서는 각 3개의 비물리 장식만 숨겨졌고 기존 충돌 해시가 유지됐다.

최종 등록 PNG까지 물색 표본 검사를 반복했다. 협곡·성소 10개 원화에서 새로 발생한 0.5타일 초과 수면 표본은 0개였다. 48PPU 등록 후 주 성소에서 색상 기준 표본 1개가 추가됐으나, 좌표 `(19.625, 50.625)`는 최종 실행의 실제 발 이동 마스크에서도 통행 불가였다. 성소 4개 사냥터와 협곡의 신규 표본은 0개다. 눈 지역은 기존 보고의 작은 얼음·물가 색 표본이 남으며, 전체 원화 검토와 물리 검증을 함께 판단해야 한다. 이 수치들을 모든 경계의 완전한 일치나 수동 전 구간 플레이의 증거로 해석하지 않는다.
