- 사냥터 이탈 시 이동 완료와 목적지 맵을 확인한 뒤 자동 사냥을 재개한다. 복귀 시간 `recovery_s`와 실패 여부 `valid`를 기록한다. 복귀 실패 행은 분석에서 제외해야 한다. 복귀 시간은 처치율 분모에서 빼지 않는다.
- 장판 회피 목적지를 매 프레임 바꾸지 않고 경계 밖 여유 거리까지 이동한다. 목적지와 직선 이동 경로의 보행 가능 여부를 검사한다. 반응 지연 0.25초는 유지한다.
- 안전 원에서 공격할 때 순간이동·돌진·뒤로 도약·분신 위치 교체를 보류한다. 일반 자동 사냥에는 적용하지 않는다.
- 새 사냥·레이드 실측 전에는 도적 사냥 속도, 닌자 원거리 사거리, 보스 패턴·HP를 조정하지 않는다.

새 화면 없는 측정(`Logs/ch3-balance-boss40/out.json`, Lv40, 솔로+AI 피해 합산 비율):

| 장비 | 파이터 피해 합 | 어쌔신 피해 합·비율 | 닌자 피해 합·비율 |
|---|---|---|---|
| raid | 311,406 | 129,572 / 41.6% | 315,450 / 101.3% |
| clear | 474,498 | 200,366 / 42.2% | 407,360 / 85.9% |

Lv50 추가 측정(`Logs/ch3-balance-boss50/out.json`, `-measureChapter3 1 -measureSets raid`): 파이터 282,532+180,162=462,694, 어쌔신 129,120+61,372=190,492(41.2%), 닌자 244,291+203,020=447,311(96.7%). 닌자는 합산 목표 안이나 어쌔신은 목표 밖이다. 6회 모두 180초 생존했고 서버 상한 사용률 최대 0.36이다. Lv50 결과도 이론 환산으로 대체하지 않는다.

과거 기록에 배율만 곱한 예상과 일치하지 않는다. 따라서 보스 방 완료 기준은 아직 통과하지 않았다. 새 봇 동작과 기존 측정 당시 코드의 차이를 분리하기 전에는 사냥·레이드 또는 보스 방 배율을 추가 조정하지 않는다. 새 사냥·레이드의 개선 효과도 아직 확정하지 않았다.

검증: Unity `GameDataExport.Export` 성공(21개 파일, 데이터 버전 `6fd32cd2e649bfac` 유지), `BuildScript.BuildWindowsQA` 성공. 보스 방 배율은 서버 내보내기 대상이 아니며 골드 카탈로그 변경도 없어 데이터 내용 변경은 없다. WSL에서 `cd server && npm test -- bossRush chapter3Lock raidsChapter3 dailyChest dailies inherit sealExchange` 한 묶음 실행으로 7개 테스트 묶음 95개 통과. 게임 화면은 확인하지 않았다.

### 1.8 어쌔신 원인 조사와 실행 금지 상태

사용자 지시에 따라 어쌔신 보스 방 배율을 0.86에서 기존 0.95로 복원했다. 닌자 1.65는 유지한다. 이번 작업에서는 게임과 측정 빌드를 실행하지 않았다. 아래는 저장돼 있던 JSON·로그 비교이며 새 실측이 아니다.

| Lv50 raid | 기존 솔로 / AI 3명 | 직전 측정 솔로 / AI 3명 |
|---|---|---|
| 어쌔신 피해 | 292,160 / 208,276 | 129,120 / 61,372 |
| 어쌔신 타격 수 | 1,617 / 1,025 | 591 / 256 |
| 파이터 피해 | 352,451 / 221,761 | 282,532 / 180,162 |
| 어쌔신 합산 비율 | 87.2% | 41.2% |

- 두 기록 모두 180초 생존, Lv50 에픽 +5 무기와 같은 장비 키다. 타격 수는 솔로 63.5%, AI 동행 75.0% 감소했다. 배율만 0.95로 되돌린 산술값도 약 45.5%라 배율 하향만으로는 하락을 설명할 수 없다.
- 확실한 봇 결함: 안전 위치 공격에서 `a_kunai`, `n_clone`을 첫 입력까지 막았다. 첫 입력은 제자리 투척·분신 버프이고 두 번째 입력만 이동이다. 이제 살아 있는 쿠나이 또는 분신이 있을 때만 후속 이동을 막는다. 이것이 전체 피해 하락을 설명하는지는 미측정이다.
- 비교 조건 결함: 측정 행을 바꿔도 회피 목적지·반응 시각·원거리 대기·스킬 순번·공격 타이머·접근 불가 목록이 남았다. 행 시작에 초기화하도록 했다. 일반 플레이 수치는 바꾸지 않는다.
- 기존 로그에는 보스 앞 대기·근접 접근·장판 회피 시간과 스킬 요청 수가 없다. 원인 확정 대신 다음 측정에 `first_damage_s`, `decision_seconds`, `skill_requests`, `equipped_skills`, `driverRevision`을 추가했다. 보스 방은 30초마다 누적 로그를 남긴다. 요청 수는 성공 시전 수가 아니며, 판단 시간은 전체 전투 시간을 모두 설명하는 완전한 분할이 아니다.
- Lv10~14 자료 `early.json`은 career가 warrior/mage 둘뿐이고 뒤쪽 블록의 행 레벨이 14로 남아 있다. 마지막 블록 로그에는 `forest_depths` 도중 `forest`, `canyon_pass` 도중 적 0명의 `canyon`으로 이탈한 기록이 있다. 따라서 이를 새 도적 확정 밸런스 결과로 재사용하지 않는다. 현재 측정기는 기본 도적을 `rogue`로 기록하며 사냥터 복귀와 실패 행 구분을 한다.
- 이론 재계산: `theory_combat.py` 보스 모델 파이터 1.00, 어쌔신 1.01, 닌자 0.71(이동 없는 모델). `theory_progress.py --measured --to 50`은 Lv40 46.0시간, 미니 미사용 3장 27.8시간이다. `--mini 20 --measured-file ../analysis/player-sim/data/measure_ch3_20261024/dotrpg-measured-ch3.json`은 3장 24.9시간이다. 서로 다른 입력 조건을 섞어 완료 판정하지 않는다.
- 5번 사냥·레이드 조정은 1번 원인 확인 및 새 실측 뒤 진행하는 의존 작업이다. 게임 실행 금지로 새 실측·클리어율 판정은 보류한다. 기본 공격·MP·XP·레이드 수치와 Lv1~40 성장 수치는 수정하지 않았다. 기존 지바크 4/16, 카마츠 1/16을 새 결과로 표시하지 않는다.

#### 대기 제거 단독 비교 (decision-trace-3-no-skilled-wait)

자료: `../analysis/player-sim/data/measure_20261026_recheck_nowait/`. Lv50 솔로+AI 피해는 파이터 537,811, 어쌔신 358,630(66.7%), 닌자 567,298(105.5%)다. 어쌔신 절대 피해는 이전 봇 대비 52.2% 증가했지만 파이터도 증가하여 상대 비율 목표는 충족하지 못했다. Lv40 raid 합계는 파이터 370,328, 어쌔신 253,967(68.6%), 닌자 385,694(104.1%); clear 장비는 525,038 / 281,411(53.6%) / 510,799(97.3%)다. 장비 조건을 합쳐 평균 내지 않는다.

배속 재검증은 어쌔신 솔로 1배속 244,265 대비 고정 스텝 209,573(-14.2%), AI 136,951 대비 149,057(+8.8%)로 솔로가 10% 기준을 초과했다. 난수 시드가 대응되지 않아 배속만의 영향으로 단정할 수 없고, 동등성 통과로 처리하지 않는다. 지바크는 5/12, 카마츠는 2/12로 절반 클리어에 미달한다.

어쌔신 안전 구역 도착 후 `escape_clearance`가 여전히 솔로 61.94초, AI 50.03초였다. 안전 목적지 선택이 지형만 검사하여 적 몸체와 겹친 칸을 고를 수 있고, 경고 밖에서도 목적지 진행이 멈춘 상태를 무제한 유지하는 결함을 확인했다. 다음 비교에서는 적 몸체와 겹친 목적지를 제외하고 경고 밖에서 0.5초간 진전이 없으면 공격 판단으로 돌아오도록 측정 회피만 수정한다.

안전 목적지 수정 레이드 결과는 지바크 6/12(50%), 카마츠 4/12(33.3%)다. 카마츠는 절반 클리어 기준에 미달하며, 모든 직업·파티별 결과는 합본 JSON 및 비교 표에 남겼다.

#### 사냥 수치 해석 제한

3장 42행 중 복귀 실패 7행은 `valid=false`로 제외한다. 유효 0킬 행은 비교에서 제외하지 않는다. 직업별 자동/숙련 지상 중앙값은 파이터 7.0/7.0, 어쌔신 7.0/9.5, 닌자 4.02/4.40킬/분이다. 지하 중앙값은 파이터 25.5/15.5, 어쌔신 10.75/19.0, 닌자 7.5/9.75이나 유효 자동 행 수가 각각 1/2/4로 달라 동일 구역 비교 없이 밸런스 근거로 쓰지 않는다.

측정 봇의 일반 자동 `leap` 사용은 0.5초 쿨이 아닌 일반 순환 주기를 따르며, 사냥 중 경험치 획득과 직업별 영웅 재사용으로 자동/숙련 사이 레벨이 달라질 가능성도 남아 있다. 행별 시작/종료 레벨과 동일 시드 재측정이 필요하다. 이 관측만으로 일반 자동 사냥이나 기본 공격/MP 수치를 바꾸지 않았다.

1~40 기존 표본을 보존하고 3장 유효 표본만 넣은 `progression-input.json`으로 `theory_progress.py --measured --mini 20 --to 50`을 계산하면 1~40 44.9시간(해당 옵션 기준), 3장 27.4시간이다. 기존 46시간 기준과 경험치 데이터는 수정하지 않았다. 불완전한 사냥 표본 때문에 확정 밸런스 통과로 처리하지 않는다.

#### 확인한 결함과 수정 범위

- 포털의 목적지 방향을 중심점 내적으로만 판정해서 왼쪽 경계 바깥에 선 캐릭터가 안쪽으로 걸어도 출구로 처리되는 결함을 로그로 확인했다. 경계 포털은 실제 바깥 방향, 내부 계단은 기존 접근 방향을 사용한다. 네 방향 진입/안쪽 이동과 내부 계단을 포함한 11개 회귀 검사가 통과했다.

- 승급(`PromoteRules.CostInto`) 그대로. 핵 수급: 지바크 { 1, 2, 2, 3 }, 카마츠 { 2, 3, 4, 6 }.

- 잠금: 결과 장비가 챕터 3 태그라 서버는 `assertOpen('item', 원본·결과)`로 막고(422 `CHAPTER_LOCKED`), 클라이언트는 `Chapter3.Enabled`가 꺼져 있으면 미리보기를 `Locked`로 보여 준다.
- 비용 = 공통 공식 골드 + 40 → 50만 받는 재료:

| 등급 | 핵 | 침식 결정(지바크) | 잿빛 인장(카마츠) | 골드 |
|---|---|---|---|---|
| 유니크 | 3 | 5 | 10 | 공통 공식: 0.25 x 10,000 x (단위(N) - 단위(10)), 무기가 아니면 80% |
| 레전더리 | 6 | 10 | 20 | 위와 같다 |

| 계승하는 강화 | +10 이하 | +11 | +12 | +13 | +14 | +15 | +18 |
|---|---|---|---|---|---|---|---|
| 유지 확률 | 100% | 90% | 80% | 70% | 55% | 35% | 22% |
| 골드(무기) | 0 | 30,000 | 113,333 | 399,048 | 860,586 | 1,568,919 | 5,714,374 |
| 골드(방어구·장신구) | 0 | 24,000 | 90,667 | 319,238 | 688,469 | 1,255,136 | 4,571,499 |

- 골드를 설계 고정값(유니크 150,000, 레전더리 400,000)에서 공통 공식으로 바꾼 근거(2026-10-22):
  1. 고정값은 강화 단계와 상관이 없어 Lv40 +18을 15만 골드에 Lv50 +18로 옮긴다. Lv50에서 새로 +18을 만드는 값은 2,322만이라 계승이 강화를 대신하는 우회가 된다. 공통 공식은 571만(4분의 1 안팎)이라 출시용 경로와 같은 비율로 막힌다.
  2. 출시용 경로가 "확률 + 누적 깎임 + 단계 비례 비용" 하나로 정해졌고(사용자 결정 "40은 50으로만", "확률형으로"), 40 → 50만 다른 비용 체계를 두면 화면·서버·문서가 둘로 갈린다.
  3. 레이드 두 곳을 계속 돌게 하는 장치는 재료라서 재료는 설계값 그대로 둔다. 등급 차이(레전더리 2배)도 재료가 맡는다. 골드는 등급이 아니라 강화 단계로 갈린다.
  4. 경제 표(5절)의 계승 칸은 +12 무기 113,333으로 바꿨다. 옛 고정 150,000은 +12와 +13 사이 값이다.
- 결과 키: 새 키는 `eq_{kind}_50_{grade}+N^k`(계승 횟수 k를 적는다). 원본 행을 소비하고 같은 키끼리만 스택한다. 보호권 이력(`enhancePity`)·착용 칸·귀속을 옮긴다. 경매 가격 키는 티어별로 분리돼 있어(`eq_*_50_*`) Lv40 시세와 섞이지 않는다.
- 서버: `inherit` 도메인 하나. 트랜잭션·행 잠금·request_id 멱등·원장(`gold_ledger`·`item_ledger` 사유 `inherit`, 마이그레이션 0049_gear_inherit). 재료도 `item_ledger` 사유 `inherit`로 빠진다. 표는 `enhance.json` `inheritTiers`(40 → 50 줄에만 `cores`·`shards`·`seals`). 이론 계산은 `Tools/balance/theory_inherit.py`.
