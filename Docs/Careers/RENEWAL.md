# 전직 스킬 재구성 · Renewal

쌍참·회천검무·삼중검파의 최신 변경은 [파이터 3스킬 변경 보고서](FIGHTER-REVISION.md)를 참조한다. 아래 세 스킬의 설명과 GIF는 변경 전 Renewal 단계 기록이다.

2026-10-05 · jaein. 전직 4직업의 일반 액티브 24개와 각성기 4개를 새로운 전달·타격 방식에 연결했다. 파이터는 추가 요청대로 두꺼운 흰 검날, 진홍색 검기와 금색 가장자리로 다시 그렸다. 저장된 36개 스킬 ID와 노드 투자·각성 획득 조건을 유지한다.

## 새 원화와 리소스

`Assets/StreamingAssets/CareerRenewal/`의 Fighter, Guardian, Arcanist, Bishop PNG는 imagegen으로 새로 제작한 실제 게임 원화다. 각 PNG는 4종 모티프 × 준비·방출·명중·잔상 4프레임으로, 최종 원화는 총 64개 독립 셀이다. 파이터 원화는 두께·밝은 검날·진홍색 궤적을 강화한 추가 제작본이다.

원본 PNG를 재축소하거나 후처리하지 않는다. 생성 원화의 불규칙한 여백은 `*.frames.json`의 자르기 좌표로 처리하며, 피크 프레임 크기를 기준으로 다른 프레임을 정렬·축소한다. Point/Clamp 보간, 밉맵 없음, GPU 업로드 후 CPU 읽기 해제를 사용한다. 작은 파편·확실한 범위 경계·상태 배지는 엔진의 픽셀 그래픽으로 조합한다.

`CareerPulse/`, `CareerReborn/`, 기존 절차 생성 시트는 이전 단계 리소스다. 현재 전직 이펙트는 Renewal PNG를 사용하며, 기존 아이콘·상태 배지·호환 그래픽은 별도로 유지했다. 새 아이콘 제작 작업으로 보고하지 않는다. 임시 외부 게임 이미지나 임시 사각형을 최종 스킬 그림으로 쓰지 않는다.

- [제작 프롬프트](RENEWAL-PROMPTS.json), [파이터 두께 강화 프롬프트](RENEWAL-FIGHTER-PROMPT.json)
- [원화·프레임 매니페스트](../../Assets/StreamingAssets/CareerRenewal/manifest.json)
- [파이터 대표 스킬 GIF](RENEWAL/fighter_gameplay.gif), [일반 스킬 전후 비교](RENEWAL/normal_comparison.gif), [각성기 전후 비교](RENEWAL/awakening_comparison.gif)
- 비교의 이전 화면은 직전 Pulse 단계 실제 게임 캡처다. 이전 클립은 1.8초이며 이후 0.6초는 마지막 프레임을 유지한다. 새 클립은 실제 2.4초 캡처다.

## 확인 결과 및 범위

상세 결과와 해시 비교는 `RENEWAL/`의 보고서를 참조한다. 모든 실행 검증은 볼륨 **0**이다. 기존 4개의 만렙 체험 저장은 그대로 유지하고 로컬 체험판의 런타임 DLL·원화를 업데이트했다.

- 전체 전직 회귀 검사: **583 통과 / 0 실패**. 28개 액티브·각성 실제 Cast 연결, 피해·회복·보호, 도발, 빙결, 관통·연쇄, 영역 이탈/재진입, 각성 시련·잠금, 저장·네트워크 카드 검증.
- 최종 원화 자르기·Point 로더·새 동작 검사: **139 통과 / 0 실패**. 64개 원화 셀, 타격이 막힌 경우와 실제 명중 구분, 8방향 검날 판정, 이동·치유 도착 시점, 이동하는 방벽, 취소·정리. 13개 스킬의 실제 2.4초 미리보기 포함.
- 상태 지속 시간 추가 검사: **69 통과 / 0 실패**. `state-results.txt`에 기록. 보호막·피해 감소·도발·유지 그림이 함께 끝나는지 확인.
- 서버 연관 검사: **87 통과 / 0 실패**, 5개 테스트 모음. 서버 TypeScript 및 Unity 런타임·에디터 코드 컴파일 성공. 기존 프로젝트 경고는 남아 있다.
- 검사에는 중복 항목이 있으므로 위 숫자를 더하지 않는다. 최종 원화 자르기 변경 뒤에는 원화·새 동작 검사, 마지막 지속 시간 변경 뒤에는 상태 검사를 추가 실행했다.
- 기본 전사·마법사의 SkillEffects와 기본 SkillCaster Cast 본문은 이전 파일과 동일함을 비교했다. 전직 모션은 조건부로만 연결했다. 상세 수치·ID 비교는 `invariants.json`에 기록했다.

실제 온라인 2클라이언트의 지연·패킷 유실 상황과 다인 대규모 전투 FPS는 이번 작업에서 측정하지 않았다. 클라이언트 예측과 호스트 판정 분리는 코드·직업 네트워크 카드·서버 검사 수준에서 확인했다. 전체 Unity 플레이어를 새로 빌드하지 않았고, 기존 로컬 플레이어에 컴파일한 런타임 DLL과 StreamingAssets를 적용해 실행 검증했다. 이전 전체 빌드에서 확인된 Unity 라이선스 제약은 별도로 해결하지 않았다.
