## 1. 목표

| 목표 | 완료 기준 |
|---|---|
| 파티 사냥이 가능한 구조 | 최대 4인 파티가 함께 싸우고, 킬·보상·사망·부활이 파티 단위로 처리된다. 파티원은 조작 주체(사람/AI/네트워크)와 상관없이 같은 캐릭터 구조를 쓴다 |

## 2. 현재 코드 상태 (조사 결과)

**이미 있는 것**
- 사이드 메뉴의 `미니던전`/`레이드` 버튼과 안내 창(`ContentScreen`, UI/WindowScreens.cs). 입장 버튼은 "준비 중" 토스트만 띄운다.
  - 문구(UI/UIRoot.cs): 미니던전 "광산 해골대장 · 1인 · 하루 3회", 레이드 "해골왕과 친위대 · 최대 4인 · 주 1회"
- 캐릭터 행동 API가 public(`TryAttack`, `TryCast`, `TryInteract`, `UseConsumable`, `FaceTowards`). `DevCapture`가 이미 입력 없이 캐릭터를 조종한다 → AI 동료의 발판.
- 스킬 판정은 `EnemyController.Active`만 대상 → 아군 오사 없음.
- 적 `Stun`/`Freeze` API, NPC 서비스로 창을 여는 경로(`NpcService` → `UIRoot.OpenService`).

**없는 것**
- 인스턴스 맵, 방/문, 맵 단위 타이머, 결과 화면. 맵은 `MapRegistry`의 일렬 체인(마을→숲→협곡→겨울)뿐.
- 보스, 슈퍼아머, 무력화, 원거리·패턴형 적. 적은 해골 1종(근접 1패턴).
- 요일·날짜 로직(DateTime은 저장 시각 기록뿐).

**파티를 막는 결합 (핵심 리스크)**

| 결합 | 위치 | 문제 |
|---|---|---|
| 캐릭터 1명 = 세션 전체 | 정적 `CharacterStats`(Progression/SkillData.cs:334), `Game.Session.PlayerMana` 등 | MP·레벨·장비·패시브·버프를 모든 캐릭터가 공유 |
| 정적 킬 이벤트 구독 | Player/PlayerController.cs:79 | 캐릭터가 N명이면 XP N배 |
| 입력 직결 | PlayerController.cs:239-262 | 모든 캐릭터가 키보드 입력대로 움직임 |
| 적 타깃 고정 | EnemyController `Target` = `Game.Player`, `Strike`는 1명만 판정 | 동료는 공격받지 않음 |
| 공격자 정보 없음 | `DamageInfo`(Combat/Damage.cs) | 킬 크레딧·어그로·딜 기여도 불가 |
| 사망 = 게임오버 | PlayerController.cs:422 | 동료가 죽어도 게임오버 |
| `Game.Player` 싱글톤 | 32개 파일 59곳(DevCapture 제외) | 카메라·HUD·픽업·포털·드롭이 1명 기준 |

## 4. 파티 구조 설계 (D1 = A 기준)

```
Game.Party (PartyManager)
 ├─ Members[0..3] : PartyMember   캐릭터 본체 = 기존 PlayerController 재사용
 │     ├─ CharacterData   직업·레벨·Progression·Equipment·MP·버프 (정적 CharacterStats에서 이동)
 │     └─ IActorInput     LocalInput(키보드/패드) | CompanionBrain(AI) | NetworkInput(향후)
 ├─ Local   이 PC가 조작하는 멤버 (카메라·HUD·토스트 기준)
 └─ Leader  포털 이동·던전 입장 권한
```

- **IActorInput**: 매 프레임 `ActorCommand`(이동, 조준, 공격, 상호작용, 스킬 슬롯, 아이템)를 만든다. PlayerController는 키 입력 대신 명령을 소비한다. 사람·AI·네트워크가 같은 캐릭터를 구동하는 것이 "파티가 가능한 구조"의 핵심.
- **공유 vs 개인**: 인벤토리·골드·퀘스트·창고는 세션 공유(로컬 플레이어 소유). HP·MP·스탯·버프·쿨다운은 멤버별.
- **전투**: `DamageInfo.attacker`를 추가해 킬 크레딧·어그로·딜 기여도를 계산한다. 적 타깃은 위협도(받은 피해 + 거리 + 타깃 유지) 기반. 적 공격은 범위 판정으로 바꿔 여러 파티원을 동시에 맞힐 수 있게 한다.
- **보상**: 처치 XP는 같은 맵의 파티원 전원에게. 필드 드롭은 로컬 플레이어가 줍는 방식 유지. 던전 보상은 결과 화면에서.
- **사망**: 파티원 사망 → 쓰러짐(동료가 옆에서 부활시키거나 부활 횟수 소모). 전원 사망 → 던전 실패. 필드에서 로컬 사망은 기존처럼 게임오버.
- **표시**: 카메라는 로컬 멤버를 따라간다(던파 방식). 좌측에 파티 프레임(HP/MP). 화면 흔들림·토스트·각성 배너는 로컬 멤버 행동에만.
- **CompanionBrain(AI)**: 리더 추종(멀어지면 순간이동 보정) → 교전(위협 대상 공격, 쿨마다 스킬) → 위험 회피(보스 예고 장판 밖으로) → 기믹 대응(보스가 방송하는 우선 타깃·목표 지점). 동료는 기존 2직업(전사형·마법사형) 재사용.
- **온라인 확장 대비(구현 안 함)**: 멤버 ActorId, 명령 스트림, 난수 판정(막기·드롭)을 권한 측으로 모을 수 있게 분리만 해 둔다.
- **호환**: `Game.Player`를 `Game.Party.Local`을 가리키는 호환 프로퍼티로 두고 점진적으로 옮긴다 → 기존 싱글 플레이 회귀 방지.

## 5. 콘텐츠 설계

### 5.0 던전 공통 프레임워크 (요일던전·레이드 공용)
- **던전 정의 데이터**: `Resources/Data/Dungeons/*.asset`(이름, 맵, 방 구성, 몬스터, 난이도 배율, 보상 테이블, 입장 규칙). 수치는 전부 데이터로 둔다.
- **인스턴스 맵**: `MapInfo`에 `instanced` 플래그(지도 창·포털 체인에서 제외). 맵 텍스트에 방 영역과 문 기호 추가.
- **방 진행(던파식)**: 방의 적 전멸 → 문 열림 → 다음 방, 마지막은 보스방. 미니맵에 방 표시.
- **DungeonRun**: 현재 방, 경과 시간, 남은 부활 횟수, 킬 수, 파티원별 기여도.
- **인원수 체력 보정**: 던파처럼 파티 인원에 따라 몬스터 체력을 늘린다. 예: 1인 ×1.0, 2인 ×1.7, 3인 ×2.4, 4인 ×3.0(데이터로 조정).
- **결과 화면**(`GameState.DungeonResult`): 클리어 시간·랭크(S/A/B/C), 파티원별 딜 기여도, 획득 목록, 보상 카드 4장 중 1장 선택(던파 클래식 방식).
- **입장 흐름**: 마을 던전 안내원 NPC 또는 사이드 메뉴 → 던전 선택 창(요일, 난이도, 파티 편성, 남은 횟수) → 페이드 → 던전 → 결과 → 마을 광장 복귀.
- **저장**: 던전 안에서는 저장·자동 저장을 하지 않고, 이어하기는 마을에서 시작. SaveData v4에 마지막 초기화 시각, 사용 횟수, 주간 레이드 귀속, 최고 랭크, 파티 편성 추가.

### 5.1 요일던전
기존 맵 테마(숲 HD·협곡·겨울)를 재사용해 새 타일 아트 없이 만든다. 맵 레이아웃은 3종을 요일끼리 공유한다.

| 요일 | 던전 | 맵 | 주 보상 | 특징 몬스터 |
|---|---|---|---|---|
| 월 | 황금 광맥 | 협곡 광산 | 골드 | 황금 해골(도망치며 골드를 뿌림) |
| 화 | 버려진 제련소 | 협곡 광산 | 강화석 | 해골 광부(돌진) |
| 수 | 마력의 묘지 | 숲 묘지 | 마력 정수 | 해골 사령술사(원거리, 해골 부활) |
| 목 | 수련의 숲 | 숲 묘지 | 경험치 | 해골 궁수(원거리) |
| 금 | 망자의 무기고 | 겨울 동굴 | 장비 드롭률 | 해골 방패병(정면 방어, 슈퍼아머) |
| 토·일 | 전 던전 개방 | — | — | — |

- 구성: 방 3개 + 보스방. 요일별 보스 1종(광산 해골대장 계열 변형).
- 난이도 3단계: 일반 / 숙련 / 달인. 권장 레벨, 몬스터 배율, 보상 배율이 다르다. 권장 전투력 표시를 위해 캐릭터 총 전투력 계산을 추가한다.
- 입장: 요일던전 전체 하루 3회 공유(06:00 초기화).

### 5.2 레이드: 해골왕 (기존 안내 문구 유지)
- 4인 파티, 보상 주 1회 귀속(목요일 06:00 초기화), 파티 공유 부활 3회.
- 구성: 친위대 전초 방 2개(해골 기사단, 사령술사) → 해골왕 보스방.

| 페이즈 | HP | 패턴 | 파티 기믹 |
|---|---|---|---|
| 1 | 100~70% | 3연타, 예고선 돌진 | 전사형이 어그로 유지 |
| 2 | 70~35% | 해골 소환, 바닥 장판 | 사령 토템 2개를 짧은 간격 안에 모두 파괴(늦으면 소환이 계속됨) |
| 3 | 35~0% | 광폭화, 전멸기 "망자의 심판" | 시전 전에 무력화 게이지를 깎으면 그로기, 실패하면 큰 피해 |

- **보스 공통 시스템**(요일던전 보스도 사용): 다중 줄 HP 바(화면 상단), 무력화 게이지(스킬별 무력화 수치, 0이 되면 그로기 + 받는 피해 증가), 슈퍼아머(패턴 중 경직·넉백 무시, 기절·빙결 효과 감소), 예고 장판(원형·직선·부채꼴), 패턴·페이즈를 데이터로 정의.
- 보상: 결과 카드(유니크·레전더리 확률), 레이드 재화(레이드 상점은 이후 확장).

## 7. 검증 방법
- 이 PC에 Unity 6000.5.9f1이 설치되어 있어 batchmode 컴파일로 오류를 확인한다.
- 기존 `DevCapture` 자동 시나리오를 확장한다: 파티 편성 → 던전 입장 → 방 클리어 → 보스 → 결과 화면 스크린샷 → report.txt.
- `Tools/CompileCheck`는 이 PC에 dotnet이 없어 사용할 수 없다.
- 조작감·난이도 같은 체감은 직접 플레이로 확인해야 한다.

## 8. 리스크
- 단계 1의 수정 범위가 넓다(핵심 약 17개 파일 + UI). 호환 프로퍼티로 흡수하고, 단계가 끝날 때마다 기존 흐름을 스모크 테스트한다.
- 길찾기가 없다(적도 직선 이동 + 막힘 감지). 던전 방은 장애물이 적은 열린 구조로 설계하고, 동료는 순간이동으로 보정한다.
- 신규 몬스터·보스 스프라이트를 코드로 그려야 한다(ProceduralArt 확장). 보스는 캐릭터의 2~3배 크기.
- 나중에 온라인 멀티(D1 = B)를 붙이면 동기화·권한 설계가 추가로 필요하다. 이번 구조는 그 준비까지만 한다.
